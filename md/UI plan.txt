Below is a full UI plan for the **Digital Church OS public frontend development** based on the uploaded frontend plan. The spec requires a **theme-based public frontend**, not one hardcoded church website, with **Christo Theme** as the first default system theme. 

# Digital Church OS Frontend UI

## Theme-Based Public Website + Christo Theme + Theme Customizer

## 1. Main UI Direction

The UI should be built around **two connected experiences**:

1. **Tenant Dashboard Website Builder UI**
   Where church admins manage their public website, theme, pages, navigation, colors, sections, preview, and publishing.

2. **Public Church Website UI — Christo Theme**
   The actual website visitors and members see when they visit a church domain.

The frontend must separate **content from presentation**, meaning CMS pages, sermons, events, giving, prayer, media, groups, campaigns, and other modules should render through theme-compatible templates instead of being locked to one design.

# 12. Visual Style Guide

## Light Mode

```text
Background: warm off-white
Surface: white
Text: charcoal
Muted Text: slate gray
Border: soft gray
Accent: tenant-selected accent
```

## Dark Mode

```text
Background: soft charcoal / deep slate
Surface: slightly lighter charcoal
Text: soft white
Muted Text: muted slate
Border: dark slate
Accent: tenant-selected accent
```

Dark mode should not be pure black. The uploaded plan specifically describes Christo Theme as soft, premium, spiritual, modern, warm, trustworthy, minimal, and cinematic but clean. 

## Shape

```text
Cards: rounded-xl
Feature panels: rounded-2xl
Buttons/badges: rounded-full
Borders: thin and soft
Spacing: generous
Shadows: soft, not heavy
```

## Icon System

Use **Lucide icons** across:

```text
navigation
cards
buttons
forms
alerts
empty states
module pages
footer contact items
media controls
event info
giving cards
```
